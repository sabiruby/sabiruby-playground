# 2026-11-03 SabiRuby 0.9.0 から建てる

SabiRuby の `docs/plans/release-0.9-plan.md` の R6（下流のバージョン上げ）。著者の判断（2026-11-03）で進めた。
着手時の先頭は main の `2acc616`（`SABIRUBY_REF` は `7f74cd1` = v0.8.0）。

## 変えたもの

- `.github/workflows/pages.yml` の `SABIRUBY_REF` を `a3a798d`（tag `v0.9.0`: `sabiruby` 0.9.0、`sabiruby-compiler` 0.6.0）に。コメントに前の 3 つを残した。
- `wasm/Cargo.lock`: `tools/build.sh` が path の依存を読み直して `sabiruby 0.8.0 -> 0.9.0`、`sabiruby-compiler 0.5.0 -> 0.6.0` に書き換えたもの（0.8.0 の commit `2acc616` と同じ形）。
- README の「Pinned versions」の SabiRuby の行と、モジュールの大きさの行に v0.9.0 の数を 1 文。

コードは 1 行も変えていない。0.9.0 は VM に足すだけのリリースで（feature `checkpoint` は既定 off、`Vm::output_sink`）、
`wasm/src/lib.rs` が呼ぶものは変わっていない。

## 確かめ

隣の `../sabiruby` を tag `v0.9.0`（`a3a798d`）の木にして、path で読んで建てた。

```
$ PATH=<binaryen 132>/bin:$PATH tools/build.sh
    Updating sabiruby v0.8.0 (…/sabiruby) -> v0.9.0
    Updating sabiruby-compiler v0.5.0 (…/sabiruby/compiler) -> v0.6.0
web/sabiruby.wasm: 2469461 bytes (853379 gzipped)
$ npm test                 18/18 fixtures match the reference output、26/26 checks
$ npm run test:browser     1 度目: 21 ok・1 FAIL、続けて 3 回: all passed
```

0.8.0 の 2,469,338 bytes から 123 bytes 増えた。

**1 度目の FAIL は「the same program without 実時間 does not wait」の 300 ms**（上限 250 ms）。命令数で進む時計の下で
`3.times { sleep 0.1 }` が待たないことを、ページの外の実時間で測る check。走らせたとき同じ PC で別の repo の cargo の build が
回っていて、load average は 13 だった。直後に 3 回続けて走らせて 3 回とも all passed。VM の変化（`sleep` の扱いは 0.9 で変わっていない）
ではなく、負荷の高いときに実時間の閾値に触れたものと読んだ。
